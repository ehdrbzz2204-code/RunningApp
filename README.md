# RunningApp
목표 기반 러닝 미션 앱


## 백엔드 MVP


1. 러닝 기록 저장 및 오프라인 재전송 시 중복 방지
2. 3km 자유 주행 3회 확인 및 초기 체력 산출
3. 사용자별 거리 또는 페이스 목표 저장
4. 맞춤 미션 추천 및 성공 여부 판정
5. 주간·월간 러닝 기록 조회


## 모바일 앱과 서버의 역할


- 모바일 앱은 GPS 측정, 로컬 저장, 연결 복구 후 재전송을 담당합니다.
- 서버는 러닝 기록, 초기 측정 진행률, 활성 목표, 미션 결과를 관리합니다.
- API에서 거리는 m, 시간은 초, 페이스는 초/km를 사용합니다. 앱은 동일 러닝을 재전송할 때 같은 `clientRunId`를 사용합니다.


## 협업


| 브랜치 | 역할 |
| --- | --- |
| `main` | 통합 테스트를 마친 시연·배포용 버전 |
| `develop` | 세 기능 브랜치를 합쳐 앱 전체를 검증하는 통합 브랜치 |
| `feature/backend` | 백엔드 API와 저장소 |
| `feature/frontend` | 프론트엔드 두 명의 공용 브랜치 |
| `feature/mission` | 미션 추천·판정 로직 |

1. 작업 전에 최신 `develop` 변경을 담당 브랜치에 반영합니다. 프론트 공용 브랜치는 서로 작업 파일을 공유하고 강제 푸시를 피합니다.
2. 기능이 검토 가능한 상태가 되면 `feature/* → develop` PR을 열고 관련 이슈 번호를 적습니다. 팀원 리뷰와 기능 테스트가 끝나면 `develop`에 병합합니다.
3. 실제 앱에서 기능이 함께 동작하는지 확인한 뒤 `develop → main` PR로 시연·배포 버전을 병합합니다.

 기술 스택과 실행 방법은 백엔드 코드가 추가될 때 문서화합니다.

## 커밋과 비밀값

- API 명세에는 예시 이메일과 `<accessToken>` 같은 자리표시자를 사용합니다. 실제 비밀번호, 발급된 토큰, API 키와 인증서 개인 키는 코드·문서·이슈·PR에 올리지 않습니다.
- 비밀값은 로컬 환경 변수 또는 `.env`로 관리합니다. 공유하는 `.env.example`에는 예시 값만 넣습니다. `.gitignore`의 제외 규칙은 이미 추적 중인 파일이나 코드에 직접 적은 비밀값에는 적용되지 않습니다.
- 실제 계정과 러닝 기록이 들어 있는 SQLite DB, 백업, 내보내기 파일은 저장소에 올리지 않습니다. 백엔드 로컬 DB는 `backend/data/`에 둡니다.
